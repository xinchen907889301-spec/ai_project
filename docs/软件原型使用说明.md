- 按网站普通页面请求读取 DataTFT 金铲铲阵容快照，校验 `App-Platform: jcc`，保留来源、抓取时间、赛季、段位和原始筛选参数。
- 本次成功获取31套S18阵容。网站评级与平均名次、前四率、登顶率分别保存；不把等级或 `score` 当成概率。

- 二三阶段主要依据已合成装备、明确指向的强化预判候选。过渡牌只作辅助，不要求已经持有四费主C。
- 同一玩家可对应多个候选；未观察、观察过期和当前潜在竞争分别显示。前期不称为确定同行。
- 简洁建议与可展开统计；默认稳健上分，可切换争取第一。
- 安卓本地界面、系统屏幕采集授权、可拖动的悬浮手动截图按钮、返回助手确认、通知栏停止。没有无障碍服务、自动点击或游戏内存读取。
- 可配置视觉模型适配接口；模型未配置时明确报未配置，手动记录仍可使用。

## 当前原型的真实边界

这不是已完成实战验证的自动助手。当前推断使用可解释的规则权重，不是训练好的胜率模型；尚未接入LLM的完整运营建议，只实现视觉模型接口与基础方向比较。没有自动侦察七家，没有后台逐帧识别、自动身份归属、全场战力评估、升级搜牌建议或每日无人值守同步。

截图流程目前是：点击截取 → 回助手 → 导入画面 → 连接视觉服务后识别（也可手动填写）→ 确认身份和内容 → 更新方向。悬浮提示“已采集”不表示“已识别”。一次只保留最后一张待确认截图；应确认后再截下一张。采集帧在手机处理，不会自动上传；点击识别后才将当前截图提交到所配置的服务。

已知测试机：荣耀Magic9（用户提供），安卓版本尚未确认。最低支持Android 10，目标API35。尚未在该实体手机验证录屏授权、横竖屏切换、系统省电行为和悬浮窗；目前不能给30秒侦察能力或识别准确率保证。

## 在电脑运行

需要Node.js20以上。应用服务本身没有第三方运行依赖。

```bash
npm ci
npm test
npm start
```

默认监听本机3000端口。用浏览器访问本机服务。当前聊天环境的工作区链接不等同部署网址；服务也没有被发布到公网。

首次可点击“体验演示局势”。阵容资料是真实网站快照，演示玩家的牌和装备是构造情景，界面持续标注演示。点击“开始新对局”清空本局后，填入实际观察内容。

自己的记录跨回合或超过90秒时要求重确认。90秒是可调整的原型保守阈值，不是已经实测的最优时效。观察时间必须合法，较早的回合或请求不能覆盖较新记录；战斗画面不能作为备战状态保存。

## 安卓安装与构建

已构建的调试APK位置见交付说明。Android手机允许安装后即可运行本地界面和手动记录；联网视觉功能另外需要可从手机访问的HTTPS分析服务。

在Android Studio打开 `android/`，或准备JDK17/21、Gradle8.10.2、Android SDK35及Build Tools35.0.0：

```bash
cd android
./gradlew :app:assembleDebug :app:lintDebug
```

`local.properties` 配置 `sdk.dir`。调试APK默认在 `android/app/build/outputs/apk/debug/app-debug.apk`，不含模型密钥。网页界面和资料快照直接打包为本地资源；更新资料后需要重建APK，本版尚未做App内数据热更新。

## 接入真实视觉模型

服务端通过环境变量配置：

- `VISION_API_URL`：支持图片和JSON输出的HTTPS Chat Completions接口。
- `VISION_MODEL`：该服务的视觉模型名称。
- `VISION_API_KEY`：模型密钥，只放服务器环境，不放前端或GitHub。
- `ASSISTANT_TOKEN`：应用连接分析服务的访问码；对外监听需要至少24字符。
- `HOST`：对外提供时配合HTTPS反向代理。默认只监听127.0.0.1。

在应用“视觉识别连接设置”填HTTPS分析服务地址和访问码。前端不会保存访问码到localStorage。服务端只处理本次截图，不将它存成文件。模型返回结果需通过目录校验并由玩家确认，不会直接写入观察记录。

用户已有视觉模型服务；当前开发环境尚未配置该服务的接口、型号与凭据，没有公开HTTPS分析地址，尚未完成真实图片识别端到端验证。接口自动测试使用明确的模拟响应，不能算作识别准确率测试。

用户随后提供的服务地址为 `https://api.deepseek.com`。具体模型名称及图片输入能力尚未核验，不能仅凭兼容Chat Completions就当作视觉模型使用。如果该型号仅支持文本，可以用于识别后的运营分析，另配图片识别模型。当前环境访问其官网文档与接口被网络策略拦截；已在环境草稿加入两个域名，待保存发布后重试。尚未配置或发送模型密钥。

## 数据刷新

```bash
npx playwright install chromium
npm run data:refresh
```

若使用系统Chromium，可设置 `CHROMIUM_EXECUTABLE`。受代理环境可使用 `HTTPS_PROXY` 及环境提供的可信 `NODE_EXTRA_CA_CERTS`。脚本保持TLS验证，使用普通页面自然发出的请求，不复制签名算法或绕过登录、挑战。

成功后原始研究快照保存在忽略目录 `.local/datatft/`；规范化资料更新到 `app/public/catalog.json`。失败时保留上一份成功资料。此命令按需运行，尚未安装每日定时任务。生产接入应进一步明确站点使用条款和数据授权方式。

## 推荐依据与限制

当前匹配权重：每种匹配成装3分、明确指向的强化7分、过渡英雄每个0.5分且最多计3个；四阶段后持有主C增加5分。它们是待作者校准的工程默认值，界面不把分数显示成概率。一般经济或战力强化尚未有完整的阵容适配映射。没有足够证据时要求补充，不能直接猜。

候选差距很小时保留多个方向。新鲜潜在同行对排序只作轻微调整，不能凭同方向就强迫放弃阵容。缺少已知必备强化的阵容被降级为条件候选，明确提示条件未满足。尚未解析的体系条件也会提醒。

数据仍有这些未知：具体补丁、`time=5`对应的统计窗口、每套阵容样本量、总体count的口径以及登场率的精确定义。因此本版为研究建议，不能把宗师数据直接解释成萌新胜率，也不能把没有记录到核心英雄解释成没有同行。

## 下一轮校准

先让作者用10—20个真实二三阶段局势检查候选方向，重点看：通用肉装是否过度指向、同套装备的多阵容分歧、强化关键条件、过渡牌的误导，以及哪些局面必须输出“证据不足”。再接入视觉模型，测关键字段准确率、身份确认耗时及准备阶段可用时长。
